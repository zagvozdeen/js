Учебный проект магистратуры по JavaScript.

## Подход к работе

- Общение и интерфейс — на русском. Предпочитать простые, понятные решения.
- Развивать проект по текущему заданию: перечисленные ниже файлы и технологии
  описывают существующую реализацию, а не ограничивают дальнейшие изменения.

## Текущая структура

Сейчас это статический сайт на HTML/CSS, который раздаёт Nginx в Docker.
Сборщика frontend и отдельного backend пока нет.

- `site/index.html` — главная и навигация.
- `site/grid.html`, `site/flex.html` — примеры CSS.
- `site/styles.css` — общие стили. При изменениях синхронизировать показанные
  на страницах примеры с действующими правилами CSS.
- `Dockerfile` — сборка на основе `nginx:stable-alpine`, установка OpenSSL.
- `nginx.conf` — раздача сайта, HTTP/HTTPS и маршрут проверки состояния.
- `docker-entrypoint.d/15-local-tls.sh` — создание локального сертификата.
- `.dockerignore` — в сборку допускаются только Dockerfile, конфигурация,
  стартовые скрипты и `site/`.
- `README.md` — инструкции запуска и публикации.

## HTTP и HTTPS

Nginx раздаёт `/usr/share/nginx/html` на внутренних портах 80 и 443.
Локально используются `http://localhost:8080` и `https://localhost:8443`.
Оба протокола работают независимо, без перенаправления HTTP → HTTPS и HSTS.
Навигационные ссылки относительные и сохраняют текущий протокол и порт.

`?v=2` в ссылках и `Cache-Control: no-store` обходят старый кэш редиректа.
При проблемах различать ответы сервера и поведение браузерного кэша.

TLS-скрипт создаёт самоподписанный сертификат для localhost, 127.0.0.1 и ::1
в `/etc/nginx/certs/`, если сертификата или ключа нет. Они не входят в образ;
перезапуск контейнера сохраняет их, пересоздание генерирует заново.
Предупреждение браузера о доверии ожидаемо.

`/healthz` возвращает HTTP 200 и `ok`; его проверяет Docker HEALTHCHECK.
Порты публикуются через `docker run -p`, а не через EXPOSE.

## Сборка и запуск

Локальный образ: `js-layout-lab:latest`. Имя контейнера: `js-layout-lab`.
Первый запуск при свободных портах и имени контейнера:

```sh
cd /Users/denchik/Projects/js
docker build -t js-layout-lab:latest .
docker run --name js-layout-lab -d \
  -p 127.0.0.1:8080:80 -p 127.0.0.1:8443:443 \
  js-layout-lab:latest
```

Исходники копируются при сборке: после изменений пересобрать образ
и пересоздать контейнер. Обычный restart новые файлы не подхватит.
Перед заменой проверить существующий контейнер.

```sh
docker ps -a --filter name=js-layout-lab
docker logs js-layout-lab
docker inspect --format '{{json .State.Health}}' js-layout-lab
```

Остановка и повторный запуск: `docker stop js-layout-lab`,
`docker start js-layout-lab`.

## Docker Hub

Публичный образ: `denchik117/js-layout-lab:latest`.
Репозиторий: https://hub.docker.com/r/denchik117/js-layout-lab

Образ поддерживает `linux/amd64` и `linux/arm64`.
Для запуска опубликованной версии заменить тег образа в команде запуска.
Docker Hub хранит образ; публичного хостинга сайта сейчас нет.

Публиковать через buildx, сохраняя обе архитектуры. Если сборщик отсутствует:

```sh
docker buildx create --name js-layout-builder --driver docker-container
```

Из корня проекта:

```sh
docker login
docker buildx build --builder js-layout-builder \
  --platform linux/amd64,linux/arm64 \
  -t denchik117/js-layout-lab:latest --push .
```

Обычный push локального образа может заменить мультиплатформенный latest
одноплатформенной версией.

## Проверка изменений

Проверять затронутые страницы, навигацию, оба протокола и состояние healthy.
Для существующих маршрутов ожидается HTTP 200 без редиректов:

```sh
curl -I http://localhost:8080/
curl -kI https://localhost:8443/
```

`-k` допускает самоподписанный сертификат. Автоматизированного набора тестов
пока нет; текущую работоспособность подтверждать свежими проверками.
