# Контекст проекта

## Назначение

Учебный проект по дисциплине JavaScript в магистратуре.

Исходное задание:
1. Создать три страницы.
2. На первой странице разместить ссылки на вторую и третью.
3. На второй странице показать пример CSS Grid.
4. На третьей странице показать пример Flexbox.
5. Упаковать сайт в Docker.
6. Опубликовать Docker-образ.
7. Дополнительно реализовать HTTPS.

Первоначальный формат сдачи — ссылка на Docker-образ.
Позже пользователь также запросил редактируемый отчёт на 2–3 страницы A4
с возможностью последующего экспорта в PDF.

Основные правила:

## HTTP и HTTPS

В nginx.conf один server обслуживает оба протокола:
- HTTP: порт 80 внутри контейнера.
- HTTPS: порт 443 внутри контейнера.
- Есть слушатели IPv4 и IPv6.
- Корень сайта: /usr/share/nginx/html.
- Главная страница: index.html.
- Кодировка: UTF-8.
- TLS 1.2 и TLS 1.3.
- Для отсутствующих файлов возвращается 404.
- Маршрут /healthz возвращает HTTP 200 и текст "ok".

Локальные адреса при принятой схеме запуска:
- http://localhost:8080
- https://localhost:8443

Переадресации HTTP → HTTPS нет.
HSTS не настроен.

Все ссылки между HTML-страницами относительные, поэтому сохраняют
протокол и порт текущего адреса.

### История исправления редиректа

Ранее браузер закэшировал постоянное перенаправление на HTTPS.
После изменения серверной конфигурации переход на flex.html
мог продолжать открывать HTTPS из-за старого кэша.

Выполненные исправления:
- В навигационные ссылки добавлен параметр ?v=2.
- Nginx отправляет Cache-Control: no-store.
- Серверный редирект отсутствует.

Параметр ?v=2 оставлен намеренно.
При повторении проблемы проверять ответы сервера отдельно от кэша браузера.

## Сертификат HTTPS

docker-entrypoint.d/15-local-tls.sh запускается при старте контейнера.

Скрипт создаёт сертификат и ключ, если соответствующих непустых файлов нет:
- /etc/nginx/certs/localhost.crt
- /etc/nginx/certs/localhost.key

Параметры:
- Самоподписанный сертификат.
- RSA 2048.
- SHA-256.
- Срок действия 365 дней.
- CN=localhost.
- SAN: localhost, 127.0.0.1 и ::1.
- При создании используется umask 077.

Сертификат и закрытый ключ не включены в Docker-образ.
При обычном перезапуске того же контейнера существующие файлы используются
повторно; новый контейнер создаёт собственную пару.

Браузер показывает предупреждение о доверии к самоподписанному сертификату.
Это ожидаемое поведение локального учебного HTTPS.

Домен и сертификат публичного центра сертификации не настраивались.

## Docker

Dockerfile находится в корне проекта.

Базовый образ:
nginx:stable-alpine

При сборке:
- Устанавливается OpenSSL.
- Удаляются стандартные файлы сайта Nginx.
- Копируется nginx.conf.
- Копируется стартовый TLS-скрипт и делается исполняемым.
- Каталог site/ копируется в /usr/share/nginx/html/.
- Объявляются EXPOSE 80 443.

HEALTHCHECK:
- Проверяет http://127.0.0.1/healthz.
- Интервал 15 секунд.
- Таймаут 3 секунды.
- Начальный период 10 секунд.
- Три неудачные попытки до признания контейнера нездоровым.

EXPOSE не публикует порты на компьютере.
Публикация задаётся параметрами -p команды docker run.

.dockerignore разрешает включать в контекст сборки только:
- Dockerfile
- nginx.conf
- docker-entrypoint.d/
- site/

README, отчёт и AGENTS.md не должны попадать в образ.

## Проверка изменений

Проверять:
1. Главная открывается и содержит обе ссылки.
2. Grid показывает шесть блоков в трёх столбцах.
3. Flexbox показывает три блока и переносит их при недостатке ширины.
4. Все три страницы доступны по HTTP и HTTPS.
5. Переходы сохраняют текущий протокол.
6. HTTP не отвечает редиректом на HTTPS.
7. /healthz отвечает HTTP 200.
8. Контейнер переходит в состояние healthy.

Пример проверки кодов ответа без следования редиректам:

```sh
for route in / /grid.html /flex.html /healthz; do
  curl -sS -o /dev/null -w '%{http_code}\n' \
    "http://localhost:8080$route"
  curl -ksS -o /dev/null -w '%{http_code}\n' \
    "https://localhost:8443$route"
done
```

Ожидаемый код — 200 для каждого запроса.
Параметр -k нужен из-за локального самоподписанного сертификата;
такая проверка не доказывает доверие браузера к сертификату.
